# 群同态旧证的跨模块重写

四道目标来自已归档的群论实验，分别是构造核上的群结构、把映射限制到核、构造两个核的交集上的群结构，以及核对群字运算的封闭性。原目标、群公理、候选理论包和 Lean 版本沿用原实验。这批题及其答案此前已经公开，适合开发验收。参见[原实验](VERSION_EVOLUTION.md)。

## 怎样发现和使用共享引理

程序用 Lean 读取已编译的旧证，从外层 `have` 取出命题类型、证明依赖和源码位置。它把局部变量按作用域抽象出来，尝试将类型形状相同的命题归到一起。若另一道题的上下文能为引理补齐参数，就用共享引理替换该处的局部证明。对于失去全部调用处的局部引理，程序尝试将它删掉。每次都重新编译各原定理，核对陈述、公理和声明依赖。

程序从群字证明中提取了保持单位元的证明，以及在已知保持单位元时核对取逆封闭性的证明。第一条替换了三份旧证中的局部证明，第二条替换了两份。核上的群结构证明里有一条局部消去引理，原来仅由保持单位元那一步使用，替换后可以删除。后续用 Lean 的 `exact?` 重证核交集中的局部命题时，第四份证明也用到了第一条共享引理。生成的 Lean 模块见[四题旧工具路线](../results/proof-refactoring-v1/)。

外层带显式类型的 `have` 是这个版本的搜索范围。抽取候选只匹配去掉绑定变量名称和标注后的结构形状，类型相同的前提若有多个可选实例就跳过该匹配。程序按源码节省的粗估排序，最终以正式核验和整组计量为准。任意中间结构的推广和重述仍需更多搜索操作。

## 比较条件和计量

逐题整理只从每道题自己的旧证寻找更短的局部表达式或重复命题，并按每题的源码词元保留较短的新证或原证。成组整理从相同的整理候选起步，可以跨证明模块提取共享引理。两种范围分别有三个方案名额。逐题范围的后两个名额没有找到同题内的重复命题。成组范围核验了两项共享方案。

成组整理后冻结已核验的共同起点。继续阶段在两种可用模块条件下执行相同的两种操作，即整理局部项和重证一处长的局部推导。程序选择整组源码词元最少的已核验方案作为输入。两侧都有两个名额，使用相同的 Lean 限额，编译命令、时间和诊断随记录保存。候选侧可导入完整理论包，旧工具侧在独立目录编译。供应商调用次数为零。

压缩输入使用各原目标固定的模块名。实验路线编号只用于查记录。共享模块在目标需要其导入时进入该目标组合的账本，每个模块计一次。在候选条件下产出的证明可移除候选导入并重新核验。成功后可以选用无包版本。对完整交付口径，每份无包路线也和完整包一同核验后计量。基础模块、原目标的规格和核验入口是共同支出。

以下各列对已核验的完整路线分别择优。四题的全部 15 种非空组合也按同样口径计算。所得最小值的范围是已尝试的路线及其投影。归档的候选包证明只用于事后重放比较。完整数据见[实验记录](../results/proof-refactoring-v1.json)。

两条共享引理合计 354 个源码词元。仅构造核时，共享路线从 422 增到 604 个词元。把构造核、限制映射和群字放在一起时，三份证明共用一个模块，从 1200 降到 1117 个词元。继续搜索后，旧证收回了原先 411 个词元差额中的 334 个，归档候选方案的词元优势还有 77 个。

候选条件下的两份新方案都通过了去除候选导入后的重放。归档的候选包证明在同样操作后被拒，因为它们实际引用了候选声明。候选侧本轮找到的证明和旧工具侧相同。归档的候选证明依然提供了一条源码词元更少的路线，联合压缩字节与表达式大小则偏向新找到的旧工具路线。

## 重放

使用 Lean `4.24.0` 和 Python `3.11` 或更高版本。命令会保留编译源码、声明清单、成功与失败日志以及 `report.json`。

```bash
python -m maam refactor-proofs \
  --suite experiments/hom_kernel_evolution/suite-v2.json \
  --archives results/evolution \
  --workdir run-proof-refactoring
```
